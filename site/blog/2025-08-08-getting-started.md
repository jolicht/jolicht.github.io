Today marks the starting point of my Symfony Event Sourcing demo project.  
The goal is to build a **command-based API** with a clean, event-driven architecture,  
and document every step along the way.

### Why Event Sourcing?
Event Sourcing allows us to:
- Keep a complete history of state changes.
- Rebuild state from past events at any time.
- Enable powerful read models for different use cases.

### What to Expect
This blog will cover:
1. **Design decisions** – from aggregates to projections.
2. **Code examples** – PHP/Symfony, explained step-by-step.
3. **Frontend integration** – a minimal UI to interact with the API.
4. **Deployment** – getting it running in the cloud.

Stay tuned — next up will be a detailed look at the **project structure** and how  
the blog, frontend, and backend will all live together in one repository.
